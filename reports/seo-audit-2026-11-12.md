SEO audit — Apartamenty Dolina Strążyska — 12 November 2026

The current local version has a substantially better SEO foundation than the deployed website. It is close enough to improve without rebuilding the site, but I would resolve the launch priorities below before calling it ready for a professional deployment. No arbitrary SEO score is assigned: code quality, indexation, rankings and business results require different evidence.

This audit includes the working tree's uncommitted and untracked files, a fresh production build, all generated HTML pages, the sitemap, local Apache serving the generated build with its actual `.htaccess`, mobile Chromium checks with JavaScript enabled and disabled, and HTTP checks against production. Application source files and existing local changes were not edited. The audit created this report and its evidence files; `npm run build` regenerated the ignored `build/` directory.

No Search Console, Google Business Profile management, analytics, backlink data or keyword-volume account was available. Rankings, current Google-selected canonicals, booking conversion rates and real-user Core Web Vitals are therefore unverified. Browser resource sizes below describe local encoded resource bodies, not measured production transfer sizes or a PageSpeed score. External fonts and the booking service were blocked during local browser checks, so booking behavior and font-related layout shifts require a separate staging test.

**Fix before deployment**

1. **Save meaningful content in the prerendered HTML, without waiting for scrolling.** Both generated homepages contain `0.0/10` and `0.0/5` review scores. They also contain 25 elements with `.reveal` but no `.is-visible`, including all six apartment cards. Mobile Chromium with JavaScript disabled confirmed that the cards remain transparent even after scrolling. With JavaScript enabled, scrolling restores the scores to 9.4 and 5.0 and reveals the cards. The text and links are present in the DOM, so this is not a claim that Google cannot discover any apartment. The defect is that the static output contains incorrect ratings and visually unavailable content, defeating part of the prerendering benefit.

   Source: [postbuild.mjs:39](/Users/kubak/Zakopane-Strona/apartamenty-zakopane/scripts/postbuild.mjs:39), [useReveal.ts:24](/Users/kubak/Zakopane-Strona/apartamenty-zakopane/src/elements/useReveal.ts:24), [motion.css:2](/Users/kubak/Zakopane-Strona/apartamenty-zakopane/src/motion.css:2), [Reviews.tsx:15](/Users/kubak/Zakopane-Strona/apartamenty-zakopane/src/components/reviews/Reviews.tsx:15). Make real scores and visible content the default. Animation should enhance that state. A snapshot mode using reduced motion is one possible implementation, but verify its saved output and the subsequent browser mount. Add a build assertion for correct review values and visible primary content; do not treat `#root > *` as sufficient proof that SEO content is ready.

2. **Remove the combined third-party `AggregateRating`.** `structuredData.ts` rescales Booking.com's 9.4/10 and Google's 5/5, then publishes a new 4.7/5 rating with 282 reviews. That combined number is not displayed to users. Google explicitly prohibits aggregating ratings from other websites for review snippets and excludes self-serving local-business reviews from its star feature. Keep the source-labelled ratings and genuine testimonials visible, with links and an update process, but remove this synthetic rating from the lodging JSON-LD. This is a structured-data eligibility problem; it is not evidence that the whole site has a ranking penalty. See [Google's review guidelines](https://developers.google.com/search/docs/appearance/structured-data/review-snippet#guidelines). Source: [structuredData.ts:18](/Users/kubak/Zakopane-Strona/apartamenty-zakopane/src/seo/structuredData.ts:18).

3. **Choose and enforce one production hostname.** Both `https://apartamentydolinastrazyska.pl/` and `https://www.apartamentydolinastrazyska.pl/` currently return 200. HTTP redirects to HTTPS but preserves whichever hostname was requested. Local canonicals, social metadata, entity IDs and the sitemap all choose `www`; the supplied `.htaccess` does not consolidate hostnames. Implement a permanent redirect from the alternate host to the selected host, preserving path and query parameters. Confirm both hosts' existing Search Console signals before changing the preference; following the current code means selecting HTTPS plus `www`. See [Google's canonicalization guidance](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls).

4. **Deploy the generated build and its routing rules together.** The current production deep-link 404s show why client navigation is not enough. The supplied `.htaccess` worked on local Apache for all 18 intended routes and preserved real 404s. Production uses LiteSpeed, so repeat these checks there after upload. Ensure hidden `.htaccess` is included, and remove stale files from earlier deployments through a controlled release process. The tracked `build.zip` contains files dated June 2024; do not use that archive as the new release. Publish a fresh build with the sitemap and prerendered route files. Keep existing `/Apartament/{id}` URLs; an SEO rewrite into descriptive slugs is not required for launch.

5. **Redirect public implementation URLs to their clean routes.** `/Kontakt.html` returns the correct static contact page with 200, but React then treats that pathname as unknown and replaces it with the noindex error page. That gives raw-HTML and JavaScript clients different pages. Redirect direct `.html` requests, including `/index.html` and `/en/index.html`, to their clean canonical URLs without redirecting internal rewrites. Test for redirect loops. Trailing-slash contact variants returned 200 locally with the clean canonical, so those are normalization cleanup rather than a demonstrated crawl failure. Sources: [.htaccess:2](/Users/kubak/Zakopane-Strona/apartamenty-zakopane/public/.htaccess:2), [index.tsx:27](/Users/kubak/Zakopane-Strona/apartamenty-zakopane/src/index.tsx:27).

**High-priority improvements for the same release**

6. **Reduce mobile image loading.** Before scrolling, the homepage requests two photos for each of six apartment cards, even though the cards are below the hero. The JPGs for the Grey apartment range from approximately 250–551 KB, and its gallery uses full-size photos as thumbnails. The sampled JavaScript-enabled mobile homepage loaded about 4.9 MB of local resource bodies before scrolling; the Grey apartment loaded about 3.36 MB. These are local observations with external requests blocked, not field performance measurements.

   Use responsive `srcset` / `sizes`, smaller thumbnail assets, modern compressed images where beneficial, and lazy loading for below-the-fold card images and non-primary gallery content. Reserve image space with dimensions or a reliable CSS aspect ratio. The existing WebP conversions are valuable, and every sampled photo has alt text; do not lose those improvements. Sources: [Apartment.tsx:12](/Users/kubak/Zakopane-Strona/apartamenty-zakopane/src/elements/apartment/Apartment.tsx:12), [ApartmentDetails.tsx:66](/Users/kubak/Zakopane-Strona/apartamenty-zakopane/src/components/apartmentDetails/ApartmentDetails.tsx:66).

7. **Fix the hero preload URL and English route detection.** The preload requests `/img/house.webp`, while compiled CSS uses `/static/media/house.28dbb6485bd5ea323941.webp`. Chromium requested both 186,824-byte files. Make the preload and rendered image use the same URL. The inline route test recognizes Polish `/Kontakt` and `/Rezerwacje` only, so English contact/booking pages also trigger an unnecessary hero preload and the wrong initial background color. Source: [index.html:22](/Users/kubak/Zakopane-Strona/apartamenty-zakopane/public/index.html:22).

8. **Make language navigation real links.** The switcher currently uses buttons with JavaScript navigation and has no `a[href]` links. Existing sitemap and head alternates already help language discovery, so English pages are not completely orphaned. Links to equivalent pages still improve crawlable navigation and work without JavaScript. Preserve the current URL-based language model and reciprocal self-canonicals; English paths do not have to be translated for SEO. Source: [LanguageSwitcher.tsx:11](/Users/kubak/Zakopane-Strona/apartamenty-zakopane/src/elements/languageSwitcher/LanguageSwitcher.tsx:11). See [Google's multilingual site guidance](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites).

9. **Improve apartment snippets and factual copy.** Titles already identify each apartment, Zakopane and the brand. Descriptions are unique but mechanically truncated from decorative opening paragraphs, often ending before the practical selling points. Write a short description per apartment that explains capacity, size, sleeping layout and a verified differentiator. For example, a factual opening for Grey can state that it is a roughly 16 m² studio for two, rather than spending the snippet on atmosphere. Keep the visible page equally specific. Do not add an invented price, walking time, view or amenity just to fill a keyword.

   Correct the Polish grammar in the Błękitny description (`ręcznie rzeźbiona i wykończona elegancka meble`). Reconcile its paragraph describing a sofa for two plus a double bed with the data describing capacity five and an additional single bed. Explain the difference between 24/7 arrival and the terms' standard stay beginning at 15:00. Verify the repeated 12-minute walks to Krupówki and the valley entrance against actual routes. These are factual checks, not established false claims. Sources: [pl/apartments.ts:108](/Users/kubak/Zakopane-Strona/apartamenty-zakopane/src/i18n/locales/pl/apartments.ts:108), [apartmentList.json:122](/Users/kubak/Zakopane-Strona/apartamenty-zakopane/src/lists/apartmentList.json:122), [pl/terms.ts:23](/Users/kubak/Zakopane-Strona/apartamenty-zakopane/src/i18n/locales/pl/terms.ts:23), [LocationMap.tsx:6](/Users/kubak/Zakopane-Strona/apartamenty-zakopane/src/components/locationMap/LocationMap.tsx:6).

10. **Clean up the entity markup.** Grey's `floorSize` is omitted because `parseFloat('ok. 16 m²')` produces `NaN`; parsing translated display text is fragile. Store a separate numeric area and keep any approximation in the visible label. `inLanguage` is attached to `Apartment` and `LodgingBusiness`, although those types are not in that property's documented domain; language metadata belongs on a `WebPage` node, while languages actually spoken by the business need an appropriate property. Add stable apartment `@id` values and consistently reference the lodging entity. Verified coordinates, beds, bedrooms and check-in/out data would make the graph more complete, but are not all mandatory for ordinary indexing. Source: [structuredData.ts:57](/Users/kubak/Zakopane-Strona/apartamenty-zakopane/src/seo/structuredData.ts:57). See [Schema.org's property definition](https://schema.org/inLanguage).

   `Apartment` and `LodgingBusiness` are reasonable descriptive schema choices. They do not automatically qualify the site for Google's vacation-rental results. That feature has a separate integration and eligibility process; adding `VacationRental` alone would not solve it. See [Google's vacation-rental requirements](https://developers.google.com/search/docs/appearance/structured-data/vacation-rental).

**Content and local search strategy**

The homepage metadata already targets apartments in Zakopane, mountain views, free parking and direct booking. Keep that focus in the visible copy too. The final source check found that the extra location/stay paragraphs seen earlier in the session were no longer rendered; retain a concise, useful property-location explanation without making the page repetitive. The next content work should answer real booking questions and distinguish apartments through practical facts, rather than adding more generic descriptions of a cosy mountain atmosphere.

| Page or area | Search intent to serve | Useful addition |
| --- | --- | --- |
| Polish homepage | `apartamenty Zakopane`, `apartamenty Dolina Strążyska`, parking and mountain-view stays | Concise, verified location and property facts; easy apartment comparison; arrival information |
| English homepage | Apartments in Zakopane, Tatra stays and direct booking | Natural English wording and clear travel/arrival information |
| Each apartment | Its name and the actual guest requirements it meets | Guests, area, separate sleeping rooms, bed types, balcony/view specifics, floor and accessibility facts |
| Contact/location | Brand address, directions and arrival | Parking entrance, practical arrival instructions, verified walking routes and public transport information |
| Booking | Availability and reservations | How the booking process works, payment/cancellation summary and contact fallback, consistent with current terms |
| Future local guide, if useful | Staying near Dolina Strążyska and planning walks | Original route advice, seasonal considerations and property-specific photos, linked back to relevant apartments |

These are intent hypotheses, not measured keyword volumes or ranking forecasts. Do not create several nearly identical pages for every keyword variation. Add a dedicated family/couples/location page only when it can supply substantial distinct information.

Google Business Profile is a separate part of the launch. Verify the existing property's profile, correct category, address, primary phone, website and booking link, map pin, amenities and current photos. Keep the Polish number as the primary business identity and clearly label the English WhatsApp contact. Maintain genuine reviews and responses and keep the website's displayed source scores up to date. Seek relevant mentions and links from actual tourism partners and local organizations. The site's existing profile links do not establish whether its Business Profile is fully configured. Google's local results consider relevance, distance and prominence; site metadata alone cannot address all three. See [Google's local ranking guidance](https://support.google.com/business/answer/7091).
